    - When bridging Phase 1 (Months 1-3) to Phase 2 (Months 4-6):

      b. Identifies Root Nodes in Graph 2: Collects any `node.id` that NEVER appears in `edge.target`.
      c. Time Translation: Loops through Graph 2 nodes, recalculating `time_step = node['time_step'] + time_offset` (e.g. 0 becomes 3).
      d. Edge Linking: Dynamically spawns transition edges connecting EVERY Leaf Node in Graph 1 to EVERY Root Node in Graph 2.

13. Engine Lifecycle & Two-Pass Generation (`simulation_worker.py`):
    - Background Worker Architecture: Uses `threading.Thread` with a `threading.Event()` called `self._stop_event`.
    - Lifecycle hook in `main.py` gracefully calls `simulation_worker.start()` on boot and `simulation_worker.stop()` on teardown.
    - Two-Pass Flow: 
      1. `_process_start_job`: Calls `generate_llm_skeleton()` to instantly build the graph topology (IDs, titles, edges, time steps). Sets job progress to 50%.
      2. `_process_enrichment_job`: Iterates over every node in the graph, calling `enrich_node_details()` to build descriptions, risks, alternatives, and fetch evidence via LanceDB. Increments job progress dynamically based on `(node_index / total_nodes) * 50`.

14. Vector Store Fallback Mechanisms (`vector_store.py`):
    - PyArrow Schema: The database relies heavily on `pa.schema([("id", pa.string()), ("embedding", pa.list_(pa.float32())), ...])`.
    - Graceful Degradation: If LanceDB binaries crash or are locked by Windows OS (a major issue resolved earlier, see Section 7), the class gracefully degrades to `_InMemoryDB` and `_InMemoryTable`.
    - Vector Math Implementation: Uses a hardcoded `_cosine_similarity` static method applying `dot / (lhs_norm * rhs_norm)` to manually calculate spatial distance when LanceDB's native `.search().metric("cosine")` isn't available.

15. Resilience Implementations (`reasoning.py`):
    - Groq HTTP Interception: The `_chat_completion` method wraps the standard HTTPx client with an exact `tenacity`-style loop:
      ```python
      for attempt in range(max_retries):
          try:
              # Execute Groq API Call
          except Exception as e:
              if "429" in str(e):
                  time.sleep(delay)
                  delay *= 2
      ```
    - This natively intercepts the `rate_limit_exceeded` errors without throwing a 500 error to the frontend UI.

16. Skeleton Generation Fallback Snippet (`simulation.py`):
    - When the 70B model fails to yield valid JSON, `generate_deterministic_skeleton` takes over.
    - Logic:
      ```python

          if i > 0:
              edges.append({"source": f"node_{i-1}", "target": f"node_{i}"})
      ```
    - This creates a perfectly linear N-node chain guaranteeing the UI graph component will never crash due to a missing root or disconnected topology.

17. External Orchestrator Code (`run_12m_chained.py`):
